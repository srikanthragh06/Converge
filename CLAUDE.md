# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Converge is a full-stack Notion-like application (early stage). See ROADMAP.md for version history and what has been built so far.

## Structure

This is a pnpm workspace monorepo.

- `apps/web/` — React + Vite + Tailwind CSS v3 frontend
- `apps/server/` — NestJS + Socket.io backend
- `packages/shared/` — shared types, constants, Zod schemas, utilities, and the BlockNote editor schema (`@converge/shared`)

## Code Style

- Use Prettier for formatting. Follow Prettier rules in all code written for this project.
- NestJS file naming: kebab-case with type suffix (e.g. `document.service.ts`, `global-exception.filter.ts`).
- Layered architecture: controllers → services → repositories. Keep business logic in services.

## Conventions

- HTTP success responses use `httpOK(data?)` from `server/src/utils/http-response.util.ts` — returns the data payload directly with no envelope. Error responses use `httpFail(message)` or `httpInternalServerError()`, which return `{ success: false, message }`. WebSocket responses use `WsResponse<T>` from `server/src/utils/ws-response.util.ts`.
- Environment config: `.env.<NODE_ENV>` takes precedence, `.env` is the shared fallback.
- All color values are defined in `web/src/theme/colors.ts`. Reference them in `editorTheme.ts` and as Tailwind classes — do not hardcode hex values elsewhere.
- Tailwind's preflight is enabled (`corePlugins.preflight: true`) — it resets base element styles (e.g. `a { color: inherit; text-decoration: inherit; }`), so an element whose native browser styling the app still wants (link color/cursor/underline, etc.) needs an explicit override in `index.css` rather than relying on the browser default. See the `.bn-editor a` hover rules in `index.css` for the pattern.
- Global client-side state lives in Jotai atoms under `web/src/atoms/`, split by domain (e.g. `atoms/auth.ts`, `atoms/socket.ts`). Prefer atoms over prop-drilling for state shared across hooks and components.
- Auth state is a single `authAtom` with shape `{ status: "loading" | "authenticated" | "unauthenticated", user: AuthResponseDto | null }`. Hydrate it on app mount via `useAuth`, which calls `GET /auth/me`.
- Socket readiness is tracked via `isSocketReadyAtom` (`atoms/socket.ts`). It is set to `true` only when the server emits `DOC_READY` — not on raw socket connect. All hooks that emit events or register socket listeners must gate on this atom.
- Route-level auth gating is done via the `authRequired` prop on the `Page` component (`src/components/Page.tsx`). Do not duplicate redirect logic in individual pages.
- Numeric route params (e.g. `documentId`) use `ParseIntPipe` in NestJS controllers. Service methods that enforce access throw 404 if the resource does not exist and 403 if the requesting user lacks the required access level.
- All functions, methods, and class attributes must have inline documentation following the standard in the `add-comments` skill.
- Socket event names are defined as constants in `@converge/shared/socket/events` (`SOCKET_EVENTS`). Never hardcode event name strings in `apps/`.
- Socket event payload types and Zod schemas live in `@converge/shared/socket`. Add new schemas there when adding new events.
- HTTP request/response types and Zod schemas live in `@converge/shared/http`. Add new schemas there when adding new HTTP endpoints that are consumed by both apps. Use `ZodHttpValidationPipe` on `@Body()` for server-side validation.
- All code shared between `apps/web` and `apps/server` belongs in `packages/shared`, not in either app.
- Database migrations live in `apps/server/src/migrations/`, named `<number>_<purpose>.ts` (e.g. `0001_create_document_updates.ts`). Each file exports `up` and `down` functions. Before picking a number, check the highest one actually present in `apps/server/src/migrations/` on disk — a separate release branch can land new migrations on `main` while this one is still in flight, and a worktree checked out before that landed won't show them, so trusting a feature branch's own commit history alone risks two files silently sharing a number.
- `DatabaseService` is provided by `DatabaseModule`. Feature modules that need DB access must import `DatabaseModule` explicitly.
- Kysely table types are defined in `apps/server/src/db/database.schema.ts`. Add new table interfaces there when adding migrations.
- Redis channel and key name constants live in `apps/server/src/redis/redis.events.ts` (`REDIS_EVENTS`, `REDIS_KEYS`). Redis is server-only — do not put Redis constants or utilities in `packages/shared`. `RedisService.acquireLock`/`releaseLock` are generic distributed-lock primitives (`SET NX PX` / `DEL`) available for cross-instance coordination; no feature currently holds a lock via them.
- `RedisService` is provided by `RedisModule`. Feature modules that need Redis access must import `RedisModule` explicitly.
- Binary data (e.g. Yjs `Uint8Array`) must be base64-encoded before JSON serialisation. Use `uint8ArrayToBase64` / `base64ToUint8Array` from `apps/server/src/utils/utils.ts`.
- Async code outside the NestJS pipeline (Redis pub/sub callbacks, `setTimeout`/`setInterval`, `EventEmitter` listeners, fire-and-forget calls) must have its own try-catch or `.catch()`. `GlobalExceptionFilter` only covers `@SubscribeMessage` and HTTP handlers — unhandled errors elsewhere crash the process.
- Document access is resolved via `DocumentAccessService.resolveAccess(documentId, userId)` — four-tier: workspace owner → explicit `document_access` row → per-doc role override (`admin_doc_access` / `member_doc_access` / `non_member_doc_access` on `documents`) → workspace-level role default. Use `hasAccess(resolved, required)` from `@converge/shared` for ordered comparisons on both server and client (`web/src/utils/utils.ts` re-exports it). `ACCESS_RANK` is also exported from `@converge/shared`. `resolveAccess` takes an optional `includeDeleted` param (default `false`) — pass `true` only when the caller needs to resolve access on a document specifically because it's soft-deleted (e.g. `restoreDocument`); every other caller keeps the default so a deleted document 404s like it never existed.
- Document CRUD lives in `DocumentService`; access management (resolve, grant, revoke, role overrides) lives in `DocumentAccessService`; Yjs in-memory state and sync live in `DocumentYjsService`; real-time presence tracking lives in `DocumentAwarenessService`; version-history checkpoints (merging `document_updates` rows into `is_checkpoint` snapshots) live in `DocumentCheckpointService`, scheduled automatically by `DocumentCheckpointSchedulerService`. All five are in the `DocumentModule`.
- Time-based background work (e.g. automatic checkpoint scheduling) uses `pg-boss`, not server-memory timers — jobs are persisted in Postgres so they survive restarts and coordinate correctly across multiple server instances with no extra locking. `DocumentCheckpointSchedulerService` is the reference implementation: `'short'`-policy queues (`boss.createQueue`) cap pending jobs per `singletonKey` at one, `boss.upsert` resets a job's delay on repeated triggers, and `boss.send` no-ops if a job is already pending. Must be started (`boss.start()`) only after the database is confirmed reachable and migrated.
- When a server-side write is enforced only deep in a pipeline that fails silently for unauthorized callers (e.g. `SYNC_DOC_SERVER` in `document.gateway.ts`, which just `return`s on insufficient access with no error response — unlike HTTP endpoints, which return a clean 403), gate the corresponding UI action's visibility on the client's own resolved access level instead of letting the user trigger it and hit a silent dead end. See the restore-checkpoint and Save Checkpoint buttons in `apps/web/src/pages/editor/` for the pattern (an `isEditable` boolean threaded down as a prop).
- Workspace CRUD and membership management live in `WorkspaceService` inside `WorkspaceModule`. Workspace HTTP routes use the `/workspaces` prefix (`WorkspaceController`).
- Document access HTTP routes use the `/document-access` prefix (`DocumentAccessController`), separate from the `/document` prefix (`DocumentController`).
- BlockNote editor extensions (custom keymaps, input rules, ProseMirror plugins) live in `apps/web/src/lib/` as module-level constants created with `createExtension` from `@blocknote/core`. Pass them via the `extensions` array in `BlockNoteEditor.create()`. Do not import `prosemirror-state` or `prosemirror-view` directly — use `editor.prosemirrorState`, `editor.prosemirrorView`, and `editor._tiptapEditor.commands` instead, since ProseMirror packages are transitive dependencies not directly accessible under pnpm's strict resolution.
- `apps/server` and `packages/shared` are both native ESM (`"type": "module"`); `apps/web` is Vite, which is ESM-native regardless. Every relative import must include an explicit `.js` extension (e.g. `from './document.service.js'`, even though the source file is `.ts`) — Node's ESM resolver does no extension-guessing the way CommonJS `require()` does.
- When importing a third-party CommonJS package (no `"exports"` map with an `"import"` condition), prefer a default import (`import x from 'pkg'`) over a namespace import (`import * as x from 'pkg'`) or named imports (`import { y } from 'pkg'`) unless you've confirmed the named bindings actually resolve. Node statically detects a CJS package's named exports via `cjs-module-lexer`, which can silently miss real exports (bit us with `ioredis` and `jsonwebtoken` — see the Native ESM Migration entry in ROADMAP.md); the `default` export is always guaranteed to be the package's full `module.exports`, regardless of what the heuristic detects.
- Non-browser callers (MCP, CLI, scripts) authenticate via API keys, not session cookies. `ApiKeyGuard` (`apps/server/src/api-key/`) resolves a `Bearer` key from the `Authorization` header to a `userId`, mirroring how `AuthGuard` stamps `userId` from a session cookie — apply it with `@UseGuards(ApiKeyGuard)` on routes meant for these callers instead of `AuthGuard`. Keys are stored only as a SHA-256 hash (`ApiKeyService`); the raw key is shown once at creation and is not recoverable afterward.
- The MCP (Model Context Protocol) server lives at `apps/server/src/mcp/` (`McpModule`/`McpController`), a single `/mcp` endpoint guarded by `ApiKeyGuard`. Tool logic for a feature lives in that feature's own module as a `<feature>.tools.ts` file (e.g. `DocumentTools` in `DocumentModule`, `WorkspaceTools` in `WorkspaceModule`) — thin wrappers with no access-control logic of their own, since the underlying service methods they call already enforce it. Register new tools in `McpController` with `server.registerTool(...)`, wrapping the handler body in `withMcpErrorHandling` (`apps/server/src/utils/mcp-error-handling.util.ts`) so internal error details are never leaked to a calling agent — mirrors `GlobalExceptionFilter`'s behavior, which this endpoint bypasses by handing raw req/res to the SDK transport. MCP-facing Zod schemas must avoid `Date`/`z.coerce.date()` — use `z.iso.datetime()` strings instead, since the MCP SDK's internal `toJSONSchema()` call (on every `tools/list`) throws on a raw `Date` type. Every MCP write path (`updateDocumentBlocks`, `restoreCheckpoint`) takes a synchronous checkpoint (source `'mcp'`) immediately before writing, via the same `DocumentCheckpointService.createCheckpointInternal` the scheduler uses — gives a human a guaranteed restore point from right before any agent edit, independent of the idle/interval scheduler's own timing.
- A Yjs CRDT document's content cannot be reverted by re-applying older update bytes onto the live doc — Yjs merging is monotonic (it only ever adds structs, never removes them), so an old update just merges alongside current content instead of replacing it. To restore a document to a past state (`DocumentService.restoreCheckpoint`, `restoreYDocFromBlocks` in `apps/server/src/utils/editor-schema.ts`), bind a real BlockNote collaboration editor to a throwaway copy of the live doc and call `replaceBlocks` to explicitly remove current top-level blocks and insert the target content — genuine forward-only delete+insert operations, the same mechanism the live editor's own restore button uses. Confirmed empirically that BlockNote's `replaceBlocks`/insert honors an explicit `id` on an inserted block rather than always generating a fresh one, so a restore reproduces the target content's exact block identities — unlike inserts inside `applyBlockOperations`, which come from parsed Markdown with no id of their own.
- The BlockNote editor schema (`editorSchema`) and its `DocumentBlock` type live in `packages/shared/src/editor/editorSchema.ts` — the single source of truth for both the client editor and any server-side BlockNote usage (e.g. MCP tools' Markdown conversion). Server-side BlockNote work (`apps/server/src/utils/editor-schema.ts`) uses `@blocknote/server-util`'s `ServerBlockNoteEditor`, which depends on a shared jsdom shim (`_withJSDOM`) for anything that isn't a pure Yjs-tree walk (e.g. Markdown parsing, mounting a collaboration-bound editor) — serialize all such calls through `withMutex` (`apps/server/src/utils/async-mutex.ts`), since the shim is a single shared, unprotected resource. Pure conversions (`yDocToBlocks`, `blocksToYDoc`) don't touch it and don't need the mutex.
- A check-then-act permission gate (read a target row's role/state to decide whether the caller may act, then write) must run inside `db.transaction().execute(async (tx) => {...})` with the read using `.forUpdate()` to lock the target row — otherwise a concurrent change to that row between the check and the write can slip past a rule like "only the owner may touch an admin." `DocumentAccessService.removeUserAccess` and `WorkspaceService.addMember`/`removeMember` are the reference implementations.
- A flex-row child that can hold variable-width content (e.g. a diff/preview panel rendering arbitrary document blocks) needs an explicit `min-w-0` — flex items default to `min-width: auto`, so without it the item silently expands to fit its content's full intrinsic width instead of respecting `flex-1`/a fixed basis, which then throws off any sibling layout (e.g. `m-auto`-centered elements inside it centering relative to that oversized, often visually-clipped width). Pair `min-w-0` on the flex item with `overflow-x-auto` on its content container so genuinely wide content (tables, long unwrapped code/text) scrolls in place instead of being clipped outright. See `CheckpointHistoryModal`/`DiffBlockNoteView` in `apps/web/src/pages/editor/checkpointHistoryModal/`.
- A circular NestJS dependency needs `forwardRef(() => X)` on both sides, but that alone isn't sufficient if either constructor parameter is explicitly typed as the real class — TypeScript's `emitDecoratorMetadata` eagerly writes that class reference into `design:paramtypes` at module-load time regardless of `forwardRef`, which still crashes (`ReferenceError: Cannot access 'X' before initialization`) on a genuine two-way circular import. Type the forwardRef-injected constructor parameter `any` instead, and assign it to a separately, normally-typed class property in the constructor body (see `DocumentYjsService`/`DocumentGateway`'s mutual dependency for the pattern).
- A worktree's dev stack runs via `docker-compose.dev.worktree.yml` — a single `server`/`web` instance (not the main file's paired `-1`/`-2` instances, which exist for multi-instance Yjs sync testing) with every host port shifted +1000 from `docker-compose.dev.yml` — rather than a per-worktree env-file override mechanism. Run it with `docker compose -f docker-compose.dev.worktree.yml up`. Keep chosen host ports off the browser's unsafe-ports blocklist (e.g. 6000/X11) — a blocked port fails every fetch/XHR client-side with `net::ERR_UNSAFE_PORT`, not just navigation.
- Google's OAuth2 token exchange requires the `redirect_uri` sent to Google to exactly match the one used in the original authorization request — never hardcode it as a static server-side config value, since that only works for whichever single origin the config happened to be set for. The client already computes its own correct `redirect_uri` (`window.location.origin + '/auth/callback'`) for the authorization request; it sends that same value alongside `code` to `POST /auth/google`, and `AuthService.exchangeCodeWithGoogleAuth` echoes it back to Google verbatim instead of reading a fixed env var.
- A boolean query param (as opposed to a JSON body field) must use Zod's `z.stringbool()`, not `z.coerce.boolean()` — `coerce.boolean()` treats any non-empty string as `true`, so a literal `?flag=false` in the URL would silently coerce to `true`. `GetLibraryDocumentsRequestSchema`'s `ignorePinnedDocs` is the reference example.
- A hook that derives local state (e.g. from `localStorage`) from an id-like prop that can change without the component remounting should re-derive that state during render — comparing the incoming prop against a tracked-previous-value state and calling `setState` conditionally in the render body — rather than in a `useEffect`. Calling `setState` synchronously inside an effect is a real lint error here (`react-hooks/set-state-in-effect`) and costs an extra render pass; the render-time comparison is React's own documented pattern for "adjusting state when a prop changes." See `useWriteLock` (`apps/web/src/hooks/useWriteLock.ts`).
- `DocumentAccessService.resolveAccess` is a single indexed `LEFT JOIN` query with a SQL `CASE` expression (not sequential per-tier queries) — same shape as `getLibraryDocuments`' access-resolution subquery. Cheap enough to call fresh on every access-gated event.
- A long-lived connection (a WebSocket, a subscription, anything that outlives a single request) must never cache a resolved access level for its own lifetime — a grant, revoke, role change, or workspace-membership change has no way to reach an already-open connection otherwise, and it silently keeps stale (often over-privileged) access until the connection happens to be re-established. `DocumentGateway`'s access-gated handlers (`SYNC_DOC_SERVER`, `REPAIR_SYNC_ACK_DOC_SERVER`, `REPAIR_ACK_DOC_SERVER`, `SYNC_DOC_TITLE_SERVER`) each call `resolveAccess` fresh per event instead of reading a value stamped at `handleConnection` time; `DocumentAwarenessService.updateUser` does the same for the presence badge's `accessLevel`. This is only affordable per-event because `resolveAccess` is a single indexed query — it is not a caching workaround, and a future long-lived connection should resolve access the same way rather than reintroducing a per-connection cache.
- RAG search lives across `DocumentEmbeddingService` (OpenAI embeddings), `DocumentIndexingService` (the partial-reindex algorithm — hash-diff plus a fixed-point chunk-closure/section-closure loop, so an edit only re-embeds the affected neighborhood, never the whole document), `DocumentRerankService` (Voyage reranking), and `DocumentRAGService` (hybrid retrieval — semantic + BM25 candidates unioned by chunk id, never RRF-fused, then reranked), all in `DocumentModule`. Re-indexing is scheduled by `DocumentIndexingSchedulerService`'s own dedicated 5s-idle pg-boss queue — deliberately separate from and shorter than `DocumentCheckpointSchedulerService`'s, since search freshness needs a tighter debounce than version history does. Exposed as one MCP tool, `searchDocumentContent`, with no caller-facing strategy parameter — the retrieval implementation stays hidden and freely upgradable.
- `DocumentYjsService.loadDoc(documentId, rebuild?)` — pass `rebuild: true` from any caller with no live socket of its own (a scheduled background job, not a gateway handler). The in-memory Y.Doc cache is only ever kept fresh via a Redis subscription established when a real client socket connects to that document on that instance; a socket-less caller has no guarantee it was ever subscribed, so the cached copy could be silently, permanently stale.
- `DocumentCheckpointService.createCheckpointInternal(documentId, source, force?)` — merges every update since the last checkpoint into a new checkpoint row, or no-ops if nothing changed since then. Neither MCP write path (`updateDocumentBlocks`, `restoreCheckpoint`) passes `force: true` anymore: if nothing changed since the last checkpoint (e.g. the idle/interval scheduler just took one), that existing checkpoint already captures the exact pre-edit state, so there's nothing to gain from forcing a duplicate row. `force` remains available (currently unused by any caller) for duplicating the previous checkpoint's content into a brand-new row when a future caller genuinely needs one tagged with its own source at that exact moment. Never pass `force: true` from a caller that branches on the returned `created` flag to decide whether to re-arm something (e.g. the interval checkpoint scheduler).
- HTTP and WebSocket payload size limits must be raised in three places together, not one: Express's body parser in `main.ts` (`bodyParser: false` plus explicit `express.json`/`urlencoded` limits), `DocumentGateway`'s Socket.io `maxHttpBufferSize`, and nginx's `client_max_body_size` — all three gate the same kind of Yjs update payload, and whichever is smallest silently becomes the real ceiling. `GlobalExceptionFilter` maps body-parser's `entity.too.large` error to a 413 rather than letting it fall through to a generic 500.
- A one-time backfill/data-migration script (not a DB migration) lives in `apps/server/src/scripts/` and is deleted after use. Bootstrap it with `NestFactory.createApplicationContext(AppModule)` — the same DI graph `main.ts` builds, minus the HTTP/WebSocket listener — rather than reimplementing service wiring; default to a dry run and gate the real run behind an explicit CLI flag.
- Fixed-window rate limiting is built directly on `RedisService.incrWithExpire(key, ttlSeconds)` (request-count windows) and `incrByWithExpire(key, amount, ttlSeconds)` (token/volume windows) — there is no `@nestjs/throttler`-based guard in this codebase (`ThrottlerModule`/`UserThrottlerGuard` were removed once every remaining caller was on a Redis-primitive guard instead). A rate limit is usually a small `CanActivate` built on these two primitives directly — see `GoogleAuthRateLimitGuard` (pre-auth, per-IP + global) and `ImageKitUploadAuthRateLimitGuard` (per-user, post-auth) for the pattern — but a `CanActivate` only ever runs once per HTTP request, so a handler whose service method loops and makes several real calls to a paid API per request (e.g. `AgentService.sendMessage`'s multi-step tool-calling loop) must check/consume its budget once per real call, at the call site inside the loop, instead (see `AgentRateLimitService`, called from inside the loop rather than as a guard). Both primitives rely on the target `INCR`/`INCRBY` being atomic — the expiry is set only once, on the call that observes the key was just created (`incrWithExpire`: count `=== 1`; `incrByWithExpire`: `TTL === -1`, since a coincidental amount match could falsely look like count `1`) — no Lua script or transaction needed. Layer multiple tiers cheapest/most-specific first (e.g. per-user, then per-workspace, then global) so a caller already over its own cap short-circuits before spending Redis round-trips on the wider tiers. When a call's real cost (e.g. token usage) isn't knowable before making it — e.g. because the provider reconstructs a growing context server-side, as with OpenAI's `previous_response_id` chaining — check that budget against the running total from *previous* calls, and only true it up with the provider's real post-call usage figure afterward, rather than pre-estimating (`DocumentEmbeddingService.checkRateLimit`'s pre-flight `countTokens` estimate only works because it controls the exact input string being sent).
- `main.ts` must call `app.set('trust proxy', 1)` (a count, not `true`) for `req.ip` to reflect the real client behind nginx — omitting it silently resolves every `req.ip` to nginx's own address; passing `true` instead of `1` trusts the entire (client-spoofable) `X-Forwarded-For` chain rather than just the one hop nginx itself appends.
- A background job step that deliberately stops early on purpose — not a real failure — should throw its own typed `Error` subclass (see `IndexingCappedError`) rather than returning a sentinel, and let the existing catch/retry/reschedule path in the job handler treat it exactly like a genuine failure. Reuses the retry/backoff logic with no new code; the only difference is not logging it as an error.
- A pg-boss job handler that needs its own retry state (e.g. `job.retryCount`/`job.retryLimit`, to decide whether a DB-tracked status should still read as pending vs. fully idle after a failure) must pass `{ includeMetadata: true }` to `boss.work` — those fields exist only on `JobWithMetadata`, not the default `Job` type.
- The in-app AI agent (`AgentModule`, `apps/server/src/agent/`) is built on the raw `openai` SDK's Responses API (`openai.responses.create`), not the Vercel AI SDK — chain a multi-turn tool-calling loop's steps via `previous_response_id` rather than reconstructing a full message history on every call; the provider's own backend carries forward prior context (reasoning items included). `agent_messages` is a display/audit log only, never read back to drive a model call. `AgentTools` wraps a feature's existing MCP tool methods (e.g. `DocumentTools`) as OpenAI function tools with no separate authorization logic of its own, same reuse principle as the MCP surface itself.
- A tool `execute()` called from inside a hand-rolled agent loop (as opposed to through an SDK's own tool-calling machinery) must catch its own thrown errors and return them as a normal value (see `withAgentErrorHandling`, `apps/server/src/utils/agent-error-handling.util.ts`) rather than letting them propagate — the loop only persists a step by awaiting `execute()`'s return value, so an uncaught throw silently drops all record the call was ever attempted from conversation history, rather than surfacing as a normal failed-call result.
